# Как внести изменение

Спасибо за интерес к проекту. Изменения лучше оформлять небольшими pull request,
каждый из которых решает одну задачу и содержит тесты для изменённого поведения.

## Локальная проверка

1. Создайте `.env` на основе `.env.example` и задайте собственный пароль.
2. Запустите приложение: `docker compose up --build`.
3. Перед pull request выполните:

   ```bash
   task check
   ```

   Ручной эквивалент:

   ```bash
   golangci-lint fmt
   go generate ./...
   golangci-lint run
   go vet ./...
   go test -race ./...
   docker compose config --quiet
   ```

Если Go не установлен локально, используйте закреплённый образ
`golang:1.26.5-alpine3.24`, а для линтера —
`golangci/golangci-lint:v2.12.2-alpine`, как показано в README.

## Правила изменений

- Не добавляйте `.env`, дампы БД, пользовательские файлы и секреты в Git.
- Не редактируйте уже применённые SQL-миграции; добавляйте новую пару `up/down`.
- После изменения HTTP-контракта обновляйте Swagger командой `go generate ./...`.
- Сохраняйте SQL рядом с методом хранилища, который его выполняет.
- Для исправления дефекта сначала добавляйте тест, воспроизводящий проблему.

CI повторяет `golangci-lint`, форматирование, Swagger, `go vet`, `govulncheck`,
race-тесты и интеграционную проверку на PostgreSQL 16.
