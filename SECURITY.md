# Политика безопасности

## Поддерживаемая версия

Исправления безопасности принимаются для текущего состояния ветки `main`.
Отдельные долгоживущие release-ветки пока не поддерживаются.

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости в открытом issue. Используйте приватный
канал владельца репозитория или GitHub Private Vulnerability Reporting, если он
включён. Укажите затронутую версию, способ воспроизведения, возможное влияние и
предлагаемое исправление.

Не прикладывайте реальные пароли, персональные данные клиентов, дампы базы и
загруженные пользователями файлы. Для воспроизведения используйте только
синтетические данные.

## Границы эксплуатации

Приложение рассчитано на размещение за TLS reverse proxy. В production обязательны
`AUTH_USERNAME` и `AUTH_PASSWORD`; PostgreSQL не должен публиковаться в интернет.
Секреты должны поступать из защищённого хранилища окружения, а Swagger следует
отключать, если документация не предназначена для пользователей production-сети.
